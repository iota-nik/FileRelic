Cyclomatic Complexity: FileRelic Example

Manual calculation for detect_file_system

1. What cyclomatic complexity measures

Cyclomatic complexity measures the number of independent control-flow paths through a function. It gives a practical lower bound for the number of tests needed to exercise each logical outcome.

For one connected function: M = number of decisions + 1

A decision is normally an if, while, for, or case. This example uses five if decisions.

2. Code being measured

std::string detect_file_system(...) {
    if (is_ntfs)  return "NTFS";
    if (is_apfs)  return "APFS";
    if (is_xfs)   return "XFS";
    if (is_ext)   return "ext-family";
    if (is_btrfs) return "Btrfs";
    return "unknown";
}

4. Hand calculation

Decision numberDecision
1Is the partition NTFS?
2If not NTFS, is it APFS?
3If not earlier types, is it XFS?
4If not earlier types, is it ext-family?
5If not earlier types, is it Btrfs?
Number of decisions = 5
M = decisions + 1
M = 5 + 1
M = 6

Therefore, the cyclomatic complexity is 6.

5. Independent paths / minimum test cases

PathExpected result
1NTFS test is true → return NTFS
2NTFS false; APFS true → return APFS
3NTFS/APFS false; XFS true → return XFS
4Earlier tests false; ext test true → return ext-family
5Earlier tests false; Btrfs true → return Btrfs
6All five tests false → return unknown

Note: Some courses count short-circuit Boolean operators such as && and || as additional decisions. This function has no compound Boolean conditions in its five tests, so the basic hand calculation is unambiguous.
